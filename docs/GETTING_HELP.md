# Get useful help

[Student home](../README.md) · [Troubleshooting](TROUBLESHOOTING.md)

## Choose the right place

| Question | Where to ask |
|---|---|
| A broken public link, unclear instruction or reproducible setup problem | A GitHub issue using the environment/help or documentation form |
| Understanding a concept or debugging your practice implementation | The lab teaching team and the support channel listed on Canvas |
| Assessment rules, marks, extensions, group arrangements or submissions | Canvas and the authorised module support channel |
| A private dataset, personal circumstance or assessed code | An authorised private channel, not a public issue |

Use the repository's **Issues → New issue** control for a public material problem.
An issue is public; review your text and attachments before submitting it.

## A helpful question contains

1. **Location:** which guide or worksheet, framework and exercise.
2. **Goal:** what you were trying to do and what you expected.
3. **Evidence:** the first relevant error or a small, non-sensitive excerpt.
4. **Environment:** Colab / VS Code / JupyterLab; OS; Python and framework versions.
5. **Attempts:** one or two checks you already tried and what changed.

For example: “In the local PyTorch setup, the terminal imports torch but the notebook
raises ModuleNotFoundError. The notebook's interpreter points outside `.venv`.
I selected the project folder but have not found the notebook kernel selector.”

Avoid posting a whole completed solution when a few non-sensitive lines describe
the problem. Do not share tokens, passwords, personal records or assessed solutions.
Screenshots may help with a menu problem; copy error text when possible so it is
readable and searchable.

## Before asking

Try the relevant [troubleshooting row](TROUBLESHOOTING.md), save your work and reduce
the problem to the smallest step that fails. You do not need to solve everything
alone before asking. Explain what you understand and where the uncertainty begins.
